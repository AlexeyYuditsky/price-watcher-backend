# Правила работы с проектом

## Коммуникация

- Отвечать на русском языке, кратко и по существу.
- Перед изменениями давать короткий план, после — список файлов и проверок.
- Не повторять уже известный контекст и вывод команд без необходимости.

## Эффективность

- Читать только относящиеся к задаче файлы; искать через `rg` и `rg --files`.
- Независимые read-only проверки выполнять параллельно.
- Использовать минимальный достаточный объём вывода команд.
- Не запускать широкую сборку, если достаточно компиляции или узкого теста.
- Не обращаться к интернету без необходимости; проверять там только изменчивые факты и официальную документацию.
- Не создавать подагентов без явного запроса пользователя.

## Разработка

- Основной язык — идиоматичный Kotlin.
- Сначала следовать существующим паттернам проекта; избегать широких рефакторингов.
- Не менять публичный API и не добавлять зависимости без необходимости и объяснения.
- Сохранять пользовательские незакоммиченные изменения.
- Сразу после создания файла делать его отслеживаемым командой `git add <точный путь>`. Не использовать для этого широкие команды вроде `git add .`, чтобы не захватить посторонние изменения.
- Не добавлять перевод строки в конце файла: последний байт должен быть содержательным, без завершающих `LF` или `CRLF`. После каждого создания или изменения файла обязательно побайтово проверять EOF всех затронутых файлов и удалять завершающие `CR`/`LF`.

## Проверки и безопасность

- После изменения запускать наиболее узкую релевантную проверку.
- Не утверждать об успешной сборке или тестах, если они не запускались.
- Не выполнять `git push`, merge, rebase, удаление файлов или сброс изменений без явного запроса.
- Не коммитить cookies, browser profiles, секреты и сгенерированные HTML-страницы.
